# k6

V3 native Linux verification also exercises a real 100 ms request timeout against
an owned nonresponding loopback route. `tools:linux:smoke` runs eleven requests
total: five successful, five HTTP 503 and one timeout, preserving native threshold
exits 0/99/99 and the twenty-request ceiling. The original `tools:k6:smoke` keeps
its ten-request contract. Both close the server/connections and remove owned files.

k6 is an opt-in standalone HTTP/performance tool. Install with
`npm run tools:install -- --tool k6`; use the existing
[pin/path resolver](../../scripts/tools.json), never a second load runner.

## Provenance and discovery

The official [release](https://github.com/grafana/k6/releases/tag/v2.3.0)
ships Windows/Linux x64 archives. Their SHA-256 values were matched against its
checksums file and GitHub asset digests on 2026-10-25. k6 uses
[AGPL-3.0](https://github.com/grafana/k6/blob/v2.3.0/LICENSE.md); distribution or
modification must respect upstream terms. This library invokes the standalone
binary locally; no Grafana Cloud enrollment or hosted execution is configured.

Use `npm run tools:help -- k6`, then append `run`, `inspect`, `archive` or
`version` for installed-version help. Invoke the resolved binary with `version`
for the actual version. Native help is authoritative; the helper's allowlist
provides convenient discovery without accepting shell strings or test scripts.

| Family | Task and effects | Prerequisite / observed evidence |
| --- | --- | --- |
| `run` | Execute an approved JS scenario; can contact arbitrary targets | Exact endpoint, request budget, one VU, duration/timeout |
| `check` / thresholds in script | Assert responses; thresholds govern process failure | Check alone does not fail process; require threshold |
| `--vus`, `--iterations`, `--duration` | Bound load | Fixed iterations and short deadline; redirects disabled |
| `--summary-export`, `--out` | Write summary or export telemetry | Explicit owned output; remote output needs separate scope |
| `inspect` | Inspect script options | Review imported modules and local paths |
| `archive` | Package script/dependencies to local archive | Owned output, potentially sensitive inputs |
| `cloud`, extension resolution | Hosted/cloud or dependency downloads | No execution in default smoke; separate authorization |

## Offline smoke and diagnostics

`npm run tools:doctor -- --tool k6` probes executable/version only.
`npm run tools:k6:smoke` launches a task-owned server on an allocated
`127.0.0.1` port. The fixed script makes five good-response requests and five
deliberately failing-response requests, with one VU, no redirects, a two-second
request timeout and ten-second scenario deadline. The server rejects requests
above twenty; the harness asserts exactly ten were observed. Expected process
exits are 0 and 99 respectively. A swallowed threshold failure fails this smoke.

The child gets a minimal environment without proxies, cloud tokens, remote
outputs, user k6 config, or automatic extension resolution. Usage reporting is
disabled. No external JS imports or DNS targets occur. The parent remains async
so the loopback server can respond. Process deadlines, server shutdown and owned
temporary-file removal run on success and failure. Cleanup failures are failures.

Missing binary, host execution policy, process timeout and unexpected threshold
exit remain failures, never latency claims. This synthetic run verifies only the
operational CLI path. Real product throughput, device behavior and production
latency remain NOT RUN until an approved application/target/budget exists.
See [native k6 documentation](https://grafana.com/docs/k6/latest/using-k6/).
